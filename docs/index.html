Introduction to Sage Updated for Sage v1.0.0

Shared repository knowledge and decision history for Humans and AI coding assistants (Claude Code, Cursor, GitHub Copilot, Antigravity, and Windsurf).

Overview & Vision

When an AI pair programmer inspects your repository, it only sees static code files at the current commit. It does not know who built a module, why a strange workaround was introduced in a PR discussion six months ago, or what architecture decisions were already settled by your team.

Sage solves this problem by connecting Git history, PR discussions, and team decisions directly into an embedded SQLite database (.github/sage/sage.db).

👑
Who Knows the Code?

Combines CODEOWNERS with recency-decay commit scoring to pinpoint both formal owners and active experts.

🔍
Why Does It Exist?

Traces files and commits back to original GitHub pull requests, PR debates, and synthesized team rationale.

📦
One Clean SQLite File

Zero servers, zero external databases. Everything lives in .github/sage/sage.db committed right to Git.

How Sage Works

Sage operates entirely locally or inside your GitHub Actions pipeline:

Architecture Diagram 
[Git Commits] + [CODEOWNERS] + [PR Discussions & Issues]
                       │
                       ▼
             [Sage Extractor Engine]
                       │
                       ▼
       [.github/sage/sage.db (Local SQLite)]
           ┌───────────┴───────────┐
           ▼                       ▼
     [Interactive UI]               [AI Assistants]
        (sage ui)            (Skills & REST API: Cursor, Claude, Antigravity)

3-Step Quick Start

1. Initialize Sage in your repository
sage init

Creates .github/sage/, prompts for an optional GitHub token for PR discussions, and generates AGENTS.md.

2. Sync your Git history & team knowledge
sage sync

Builds or updates the embedded knowledge graph inside .github/sage/sage.db in seconds.

3. Explore your codebase
# Launch the interactive architecture visualizer
sage ui

# Get a compact summary of repository knowledge
sage overview

# Query knowledge or search stored records
sage query "auth"

Why Agent Skills?

When an AI assistant has a Skill installed, it understands what CLI tools and commands exist on your machine. Rather than filling your precious LLM prompt context window with thousands of lines of Git logs, the agent inspects the architecture graph and queries file details via sage ui --no-browser or targeted SQL queries via sage query on demand!

💡 Instant Discovery

Once configured, whenever you ask your agent "Who should review this PR?" or "Why does this auth retry loop exist?", it calls Sage behind the scenes and returns verified ground truth!

# Sage Skill: Repository & Team Brain

When working in a codebase equipped with Sage, do not guess who wrote code, who owns it, or why an architectural pattern exists. Use the `sage` CLI or Sage MCP tools to query the local SQLite knowledge base (`.github/sage/sage.db`) directly.

## Available Agent Commands

### 1. High-Level Context (Quick repository understanding)
Run to get compact statistics and architecture knowledge without bloating your prompt context window:
```bash
sage overview
```

### 2. Interactive Architecture Visualizer & REST API
Launch the local web visualizer and embedded REST endpoints:
```bash
sage ui
```
Flags:
- `--port <number>`: Port to run the server on (default: `8080` or next open port).
- `--no-browser`: Start the server without automatically launching the browser.

**API Endpoints:**
- `GET http://127.0.0.1:8080/api/graph`: Returns domain clusters, member files, and dependency edges.
- `GET http://127.0.0.1:8080/api/file?path=<path>`: Returns detailed inspection data (role, exports, dependencies, owner, experts, decision lineage).

### 3. Custom SQL & Record Queries
Run targeted queries directly against `.github/sage/sage.db`:
```bash
sage query "SELECT name, email, recency_score FROM people ORDER BY recency_score DESC LIMIT 5"
```
Or search for keyword records:
```bash
sage query "auth"
```

Model Context Protocol (MCP) Server Setup

Sage comes with a native Model Context Protocol (MCP) server over standard I/O (stdio). This allows Claude Desktop, Cursor, and Antigravity to call Sage tools natively as function calls:

MCP Server Config (claude_desktop_config.json or Cursor MCP) 
{
  "mcpServers": {
    "sage": {
      "command": "sage",
      "args": ["mcp"]
    }
  }
}

The MCP server automatically exposes 4 tools to your AI assistant:

  • sage_who_owns: Takes {"path": "..."} to return formal owner and recent experts.
  • sage_why: Takes {"target": "..."} to return multi-hop PR decision lineage.
  • sage_overview: Returns high-level graph statistics.
  • sage_query: Executes direct SQL queries or keyword searches against the knowledge base.

GitHub Action Usage diamondosas/sage@v1

Keep your team's knowledge graph continuously up to date inside GitHub Actions with zero server infrastructure.

Action Overview

The official Sage GitHub Action (diamondosas/sage@v1) automatically:

  1. Installs the native Sage CLI on the runner (no Go compiler or Node.js required).
  2. Connects to the GitHub API using the runner's ephemeral token to fetch PR discussions and reviews.
  3. Scans the latest Git commits and regenerates .github/sage/sage.db.
  4. Runs decision summarization with your chosen LLM provider (Google Gemini, Groq, OpenAI, Anthropic, or Ollama).

Action Inputs & Parameters

The action accepts the following configurable inputs:

Input Name Required Default Description
github_token No ${{ github.token }} GitHub token for fetching PR discussions, comments, and linked issues.
llm_provider No google LLM provider for decision summarization. Options: google, openai, anthropic, ollama.
llm_api_key No "" (empty) API key for the selected LLM provider (e.g. Gemini, Groq, or OpenAI). If omitted, Git commit graph sync still completes!
max_commits No 500 Maximum recent commits to scan for recency-decay scoring and touched files.

Standard Push / Merged PR Workflow

This workflow triggers whenever commits are pushed to main or when a pull request is merged:

.github/workflows/sage-sync.yml 
name: Sage Knowledge Graph Sync

on:
  push:
    branches: [ main ]
  pull_request:
    types: [ closed ]
  workflow_dispatch:

permissions:
  contents: write
  pull-requests: read

jobs:
  sync:
    name: Sync Repository Knowledge
    if: github.event_name != 'pull_request' || github.event.pull_request.merged == true
    runs-on: ubuntu-latest

    steps:
      - name: Check out repository
        uses: actions/checkout@v4
        with:
          fetch-depth: 0 # Full commit history needed for Git graph

      - name: Run Sage Action
        uses: diamondosas/sage@v1
        with:
          github_token: ${{ secrets.GITHUB_TOKEN }}
          llm_provider: 'google'
          llm_api_key: ${{ secrets.GEMINI_API_KEY }}
          max_commits: 500

      - name: Commit & Push Knowledge Database
        run: |
          git config --local user.email "action@github.com"
          git config --local user.name "Sage Bot"
          if [ -d ".github/sage" ]; then
            git add .github/sage
            git diff --staged --quiet || git commit -m "chore(sage): update knowledge graph [skip ci]"
            git push || true
          fi

Scheduled Cron Job Workflow Copy-Paste Ready

Run Sage on a scheduled cron timer to automatically re-index commit graphs, update expertise decay scores, and synthesize new PR decisions every night.

Why Use a Cron Job?

In active repositories where multiple developers merge dozens of PRs daily, running an automated cron job (e.g. nightly at 2:00 AM UTC) offers major advantages:

  • Zero Delay on Developer PRs: Developers don't wait for indexing during individual review cycles.
  • Recency-Decay Accuracy: Recency scores for code experts decay naturally over time. A scheduled run recalculates scores so recent active contributors stay fresh.
  • Automatic Database Maintenance: Keeps the SQLite knowledge store (.github/sage/sage.db) lean, vacuumed, and synced to Git with zero manual commands.

Complete Ready-to-Copy Cron Workflow

Copy this complete file into .github/workflows/sage-cron-sync.yml in your repository:

.github/workflows/sage-cron-sync.yml 
name: Sage Nightly Knowledge Sync

on:
  # Run automatically every night at 2:00 AM UTC
  schedule:
    - cron: '0 2 * * *'
  
  # Trigger on pushes to main / master
  push:
    branches:
      - main
      - master

  # Allow manual 1-click runs from the GitHub Actions tab
  workflow_dispatch:

# Permissions required to read PRs and push the updated SQLite database
permissions:
  contents: write
  pull-requests: read

concurrency:
  group: sage-sync-${{ github.ref }}
  cancel-in-progress: true

jobs:
  sage-sync:
    name: Sync Knowledge Graph & Expertise
    runs-on: ubuntu-latest

    steps:
      # Step 1: Checkout the full Git history
      - name: Check out repository (full history)
        uses: actions/checkout@v4
        with:
          fetch-depth: 0 # CRITICAL: fetch-depth: 0 gives Sage full commit history

      # Step 2: Execute Sage GitHub Action
      - name: Run Sage Sync Action
        uses: diamondosas/sage@v1
        with:
          github_token: ${{ secrets.GITHUB_TOKEN }}
          llm_provider: 'google'
          llm_api_key: ${{ secrets.GEMINI_API_KEY }}
          max_commits: 1000

      # Step 3: Commit and push updated .github/sage/sage.db
      - name: Commit & Push Updated Knowledge Base
        run: |
          git config --local user.email "action@github.com"
          git config --local user.name "Sage Bot"
          
          if [ -d ".github/sage" ]; then
            git add .github/sage
            # Commit only if changes were generated; [skip ci] prevents recursive triggers
            if ! git diff --staged --quiet; then
              git commit -m "chore(sage): nightly knowledge graph update [skip ci]"
              git push origin ${{ github.ref_name }}
              echo "✓ Successfully pushed updated Sage database to repository"
            else
              echo "ℹ No changes detected in .github/sage; skipping commit."
            fi
          fi
✅ Ready to Use!

Just click the Copy button above, save the file to .github/workflows/sage-cron-sync.yml, add GEMINI_API_KEY (optional) to your Repository Secrets, and commit!

Program & Repository Layout

Here is the clean repository layout when using Sage with GitHub Actions and Agent Skills:

Recommended Repository Structure 
my-awesome-project/
├── .github/
│   ├── sage/
│   │   ├── sage.db           <-- The single SQLite database (committed to Git)
│   │   └── config.json       <-- Local repository config (commit depth, branch)
│   └── workflows/
│       └── sage-cron-sync.yml <-- The scheduled cron action workflow
├── AGENTS.md                  <-- System instructions read by AI coding agents
├── CODEOWNERS                 <-- Formal ownership definitions
├── src/                       <-- Your application source code
└── README.md                  <-- Project documentation
How Each Component Interacts:
  • The Cron Job runs nightly in GitHub Actions, pulling PR discussions, computing expertise scores, and writing to .github/sage/sage.db.
  • The Commit Step pushes the updated sage.db file back to your repository with [skip ci].
  • Developers & AI Agents pull the branch and immediately benefit from up-to-date ownership and decision history without running extra sync commands locally.

Permissions & Secrets Explained

Item Type Why It Is Needed
contents: write Workflow Permission Allows the workflow to commit and push the updated .github/sage/sage.db file back to the repository branch.
pull-requests: read Workflow Permission Allows Sage to query merged PRs, titles, descriptions, review comments, and linked issues.
fetch-depth: 0 Checkout Step Option Tells actions/checkout to fetch full commit history rather than a shallow single-commit clone.
GITHUB_TOKEN Runner Secret Ephemeral GitHub token provided automatically by GitHub Actions—no manual secret creation required!
GEMINI_API_KEY Repository Secret (Optional) API key for Gemini (or Groq / OpenAI) for synthesizing multi-sentence PR decisions. If not provided, Git commit and ownership graph indexing still works completely!

CLI Command Reference Terminal Commands Cheat Sheet

Use the Sage CLI on your machine to query ownership, trace decisions, inspect repository statistics, or query the database directly.

sage init

Initializes the repository with the .github/sage/ directory and generates AGENTS.md.

sage init [--force] [--token <github_token>]

sage sync

Scans Git commits, CODEOWNERS, and GitHub PR discussions to build or refresh the local SQLite knowledge graph.

# Standard sync
sage sync

# Force full re-scan of entire commit history
sage sync --full

sage ui [--port <number>] [--no-browser]

Launches the local interactive architecture visualizer web UI with embedded static assets and REST API endpoints (/api/graph, /api/file) for inspecting domain clusters, file owners, experts, and decision lineage.

sage ui --port 8080

sage overview

Prints high-level repository knowledge statistics without bloating the AI context window.

sage overview

sage query "<sql_or_keyword>"

# Search by keyword

# Direct SQL query

Architecture & FAQ Security • Privacy • Storage

Frequently asked questions regarding storage, privacy, and GitHub Actions execution.

Single-File SQLite Storage

Unlike heavy graph databases that require external daemon services, Docker containers, or cloud subscriptions, Sage stores everything inside one compact SQLite database file:

.github/sage/sage.db

Even in repositories with thousands of commits, sage.db is typically only 1 MB to 5 MB in size. It does not require Git LFS and can be checked directly into source control.

Privacy & Local-First Design

Does Sage send proprietary code to external cloud servers?
No. Git commit history parsing, author mapping, CODEOWNERS resolution, and SQLite database storage happen 100% locally on your machine or inside your GitHub Actions runner.

When PR summarization is enabled, only commit messages and PR comment discussions are sent to the LLM provider you configure (e.g. Gemini or Groq), never your entire private repository code.

Infinite Loop Prevention

Will committing .github/sage/sage.db from a workflow trigger infinite CI loops?
No. The cron workflow includes [skip ci] in the commit message: 

git commit -m "chore(sage): nightly knowledge graph update [skip ci]"

GitHub Actions automatically ignores commits containing [skip ci], preventing recursive builds.

Offline Operation

Can Sage be used without any LLM API key or internet access?
Yes! All Git history indexing, recency-decay expertise calculation, CODEOWNERS lookup, sage ui, sage overview, and sage query function 100% offline without any API keys or network requests.
